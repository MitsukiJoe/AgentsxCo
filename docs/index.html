01 · Why

多 Agent 协作，卡在三个地方

不是模型不够聪明，而是组织方式让人和 Agent 都在内耗。

🪟

多对话分散注意力

左侧一排独立对话，任务散落在各自窗口，人要来回切换、手动同步背景，精力被窗口管理切碎。

🧩

临时零工的协作断层

Main + Sub-agents 用完即毁、彼此不能对话，上下文全靠主代理传话，既累又容易丢细节。

📢

菜市场群聊的无序与脆弱

把 Bot 全混进一个群：抢话、越权改代码、倾倒终端日志，一处卡死整条流水线崩溃。

02 · Inspiration

灵感来自 Grok Bot，
但不再被一家模型绑住

深度使用 Grok Bot 时，我们摸索出一套极顺手的团队管理方式：

  • 多个常驻角色：既能单独私聊，也能拉进群里协同
  • 主助手先把一句需求扩充完整，再拆成小任务去群里 @ 不同的人
  • 要求分两步做的事，它真的只先派第一步，做完之前绝口不提第二步
  • 群里专人反复审核迭代，总助手确认无误后才交回给你
⚠ 唯一的限制：所有角色只能用 Grok 自家模型
🎛️

跨模型自由混搭

点任意角色切换模型。人格与职责不变，只换算力——让擅长审美的去设计，擅长工程的去写码，便宜高频的去巡检。

⟷ 人格 × 模型解耦示例编排，可完全自定义
03 · Free-form canvas

团队结构由你画，不是固定模板

“总秘书、设计原型群、设计质疑、意见收集员”都只是玩法举例。你可以只对接 1 个总秘书，也可以直接对接几位组长，或者像传统多对话一样与每个角色 1v1，需要配合时再拉群。

04 · Persona × Model × Rules

人格、模型、规则，三者彻底解耦

每个角色一份独立 RoleProfile：换模型不换人格；轻量角色可关闭全局 AGENTS.md 继承；上级派单时可临时指定模型，任务期内锁定以保住 KV Cache，结单自动恢复。

05 · Architecture

对上极简 1v1，对下全透明玻璃房

切换链路看信息怎么流动；点击任一节点查看它的模型、权限与职责。

链路步骤
    06 · Stage gate & review

    分步闸门扣留 × 收集员 → 秘书二审

    一次交代两步，只放第一步进群，从根上杜绝注意力稀释与需求串味；外部意见先经只读收集员提炼、秘书二审过滤，再带着完善建议和可选方案交给你拍板。

    07 · Hierarchical dispatch

    分级派活矩阵：谁能 @ 谁，内核说了算

    拒绝无序互派。每次 dispatch 前内核强制校验 dispatchScope，越级请求被拦截并上报总秘书。层级与范围均可自定义。

    角色层级（可自由编排）dispatchScope允许派活与 @ 唤醒的范围写文件与执行权限
    👩‍💼 总秘书
    		company_all可分派给团队所有人与所有项目群全局调度、扣留阶段、签发 / 回收施工证
    🧑‍✈️ 项目组组长
    		group_internal仅限本项目群内部成员拆包派活与收口本群黑板维护与组内施工证流转
    🔎 专职质疑 / 质检
    		group_review本群全部创作成员（定点打回与放行）只读检索 + 运行真实测试 / 视觉探针 + 签发结论
    🛠️ 组内成员
    		peer_assist仅限同群搭档之间互相派活互助（如前后端对接口）持施工证（Mandate）期间解锁对应目录写权限
    👂 意见收集员
    		report_to_secretary_only仅允许私聊总秘书上报情报，禁止在研发群派活纯只读（read_only_observer）
    08 · Full-strength KV cache

    满血 KV 缓存 × 防炸施工证接力

    具名持久会话让 [人设 + 岗位规则 + 工具定义] 前缀跨轮次字节锁定，新消息只作为尾部增量信封追加——原生 85%–94% 命中。写权限跟“事”走而不跟“人”走，卡死的成员一键 handback，施工证单事务过户给替补。

    ⚡

    前缀锁定 + 尾部增量信封

    91.4%缓存命中
    稳定前缀（字节锁定）
    人设
    岗位规则
    工具定义
    群聊消息一律标记为 Context-only，只追加在尾部，不触发写操作，也不打碎历史 KV。
    🪪

    施工证跟事不跟人

    只有立项签发的施工证（Mandate）才解锁文件写入。成员中途卡死或报错时，调用 handback（或由秘书 / 组长改派），施工证在单事务内秒级过户。

    09 · Portable company.json

    整支团队一个文件，换宿主也能整包迁移

    部门群、角色人设、规则开关、派活权限全部收敛在零密钥的 company.json。分享给使用不同宿主的人，对方的 Agent 会读取它并自动绑定到本地已有的模型。

    "modelSlot": "tier:chief-secretary",

    "dispatchScope": "company_all"

  "employees": [{
    "seatId": "visual-designer",
    "modelSlot": "tier:designer",

    "inheritGlobalAgentsMd": false,
    "allowTaskModelOverride": true,
    "dispatchScope": "peer_assist"
  }, …]
}
